# מנוע בדיקת נראות במנועי AI

בודק אוטומטית האם עסק מופיע בתשובות של **ChatGPT**, **Gemini** ו**תשובות ה-AI של גוגל**, מצלם כל תשובה, ומייצר דוח בעברית.

עובד דרך **דפדפן אמיתי** ולא דרך API — כי ה-API מחזיר תשובות שונות ממה שהלקוח באמת רואה, ובלי דפדפן אין צילומי מסך.

---

## הדרך הרגילה לעבוד — התוכנה

אחרי ההתקנה, אין צורך בפקודות ואין חלון שחור. לחיצה כפולה על
**מנוע בדיקת נראות** בשולחן העבודה פותחת חלון תוכנה, בלי סרגל כתובות ובלי לשוניות.

התוכנה בנויה בשלוש לשוניות, לפי סדר העבודה — אותו מבנה ואותה זהות ויזואלית
של הכלי הידני:

| לשונית | מה עושים בה |
|---|---|
| **1. הגדרה** | פרטי העסק, המתחרים, ו**"צור את 10 השאלות"** |
| **2. הרצה** | בחירת מנועים, התחלת בדיקה, וטבלת הבדיקות עם כפתור **אימות** |
| **3. דוח** | הפקת דוח מהבדיקות שסומנו, השוואה למדידה קודמת, ומיתוג |

הפלט של כל פעולה רץ בתחתית המסך בזמן אמת.

**לסגירה:** כפתור **"סגור את התוכנה"** בפינת המסך. אין חלון נוסף לסגור.

**לעדכון:** כפתור **"עדכן"** לידו. הוא מוריד את הגרסה האחרונה ומתקין אותה,
ובסוף מבקש לסגור ולפתוח מחדש. הנתונים שלך — מסד הנתונים, הדוחות והמיתוג —
אינם בגיט, ולכן העדכון לא נוגע בהם. קובץ מהפרויקט ששונה מקומית כן יוחזר
לגרסת המקור, והוא נרשם בפלט לפני שזה קורה.

`RUN-ME.bat` נחוץ רק להתקנה הראשונה.

**איך זה בנוי:** `GEO.vbs` מריץ שרת קטן ופותח מולו חלון דפדפן. השרת מאזין
**רק** על `127.0.0.1` — הוא לא נגיש מהרשת, לא מהאינטרנט ולא ממחשב אחר.

**שלוש הערות:**

* לחיצה שנייה על הקיצור לא פותחת תוכנה שנייה — היא מחזירה אותך לחלון הקיים.
* אם משהו לא נפתח, `GEO.bat` מריץ את אותו דבר **עם** חלון מעקב, ומה שקרה נשמר
  גם ב-`data/app-log.txt`.
* להרצה מהטרמינל: `npm run app`. לשינוי הפורט ערוך את `PORT` ב-`src/app.js`.

הפקודות שבהמשך המסמך עדיין עובדות, והתוכנה מריצה בדיוק אותן. הן נשארות כאן
לאבחון תקלות ולעבודה מרחוק, לא לשימוש יומיומי.

## התקנה

צריך **Node.js גרסה 20 ומעלה**. לבדיקה: `node -v`

```bash
cd geo-engine
npm install
npx playwright install chromium
```

בדיקה שהכל תקין:

```bash
npm test
```

> **ב-Windows:** אם מופיע `npm.ps1 cannot be loaded because running scripts is disabled on this system` — זו חסימת ברירת המחדל של PowerShell על הרצת סקריפטים, לא בעיה בפרויקט. תיקון חד-פעמי, לחשבון שלך בלבד ובלי הרשאות מנהל:
>
> ```powershell
> Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
> ```
>
> לחלופין אפשר לעקוף את npm ולהריץ ישירות: `node test/logic.test.js`

אמור להציג 117 בדיקות לוגיקה, 15 בדיקות-חוזה, 67 בדיקות ממשק ו-8 בדיקות משגר שעברו. **הן רצות בלי אינטרנט ובלי דפדפן** — הן בודקות את לוגיקת הזיהוי והציון, את ההתאמה בין הייצוא לכלי הידני,
ואת הניתוב והוולידציה של הממשק. בדיקות הממשק רצות על מסד נתונים זמני ולא נוגעות בנתונים שלך.

## הרצה ראשונה

### 1. הגדרת לקוח

בתוכנה, לשונית **1. הגדרה**. בוחרים לקוח קיים לעריכה, או **"+ לקוח חדש"**.
ממלאים שם עסק, תחום, עיר, אתר ומתחרים (שורה למתחרה) — ולוחצים
**"צור את 10 השאלות"**. נבנות עשר שאלות מוכנות לעריכה, ואז **שמור לקוח**.

**איך השאלות נבנות:** תבניות, לא מודל שפה — עשר הזוויות שלקוח אמיתי שואל
(מי מומלץ, תן 5 המלצות, מחירים, ביקורות, איך בוחרים, אזור מורחב). אין מפתח
API, אין עלות והתוצאה צפויה. המחיר הוא שהניסוח לא תמיד מושלם, ולכן זו
**הצעה בתיבת עריכה** ולא רשימה סגורה — עבור עליה ותקן.

השדה שהכי משפיע הוא **התחום**: כתוב אותו כמו שלקוח שואל, לא כמו שכתוב בח.פ.
"קניית דגים טריים" עדיף על "מסחר קמעונאי בדגים".

המבנה זהה לזה של הכלי הידני, בכוונה — כדי שמדידה משם ומדידה מהמנוע יהיו
ברות השוואה.

עריכה של לקוח שכבר נמדד היא בטוחה: שאלה שנשארת שומרת את התוצאות שלה, שאלה
שנמחקת מכובה ולא נמחקת, כדי שדוחות ישנים יישארו שלמים.

מהטרמינל, אם אתה מעדיף קובץ:

```bash
node src/cli.js client:add clients/example.json
```

**השדה הכי חשוב הוא `nameVariants`.** בעברית אותו עסק נכתב בכמה צורות — "גולד פיש", "גולדפיש", "גולד שיווק", "Gold Fish". בלי הרשימה הזאת המערכת תדווח "לא מופיע" גם כשהוא כן מופיע. אותו דבר לכל מתחרה.

### 2. התחברות ל-Gemini

**גוגל חוסמת התחברות מדפדפן שנפתח על ידי אוטומציה** ומציגה "ייתכן שהדפדפן או האפליקציה לא מאובטחים". זו לא תקלה שאפשר לעקוף, וגם לא כדאי לנסות — כל הסוואה היא משחק חתול-ועכבר מול גוגל.

לכן Gemini עובד הפוך: **פותחים את הדפדפן האמיתי שלך, מתחברים בו כרגיל, והמנוע מתחבר אליו מבחוץ.** גוגל רואה דפדפן רגיל, כי הוא באמת רגיל.

```bash
node src/cli.js browser
```

נפתח Chrome או Edge שמותקן אצלך, בפרופיל נפרד תחת `data/browser-profile` — ההתחברות לבדיקות מבודדת לגמרי מהדפדפן היומיומי. התחבר לחשבון הייעודי, חכה שממשק Gemini ייטען, **והשאר את החלון פתוח.**

ואז:

```bash
node src/cli.js run goldfish --engine=gemini --cdp
```

הדגל `--cdp` אומר "אל תפתח דפדפן, התחבר לזה שכבר פתוח". החלון חייב להישאר פתוח לאורך הריצה — שם יושבת ההתחברות. בסיום המנוע מתנתק ולא סוגר אותו, כך שההתחברות נשמרת לריצה הבאה.

> **חשוב: השתמש בחשבון גוגל ייעודי לבדיקות.** לא בחשבון האישי ולא בחשבון העסקי. אוטומציה של הממשקים האלה עלולה לנגוד את תנאי השימוש, והסיכון המעשי הוא חסימת החשבון.

`node src/cli.js login gemini` עדיין קיים, אבל גוגל חוסמת אותו ברוב המקרים. השתמש ב-`browser`.

ChatGPT וגוגל עובדים בלי התחברות ובלי `--cdp`.

### 3. ריצה

```bash
node src/cli.js run goldfish
```

הדפדפן ייפתח **גלוי** — זה מכוון, דפדפן מוסתר נחסם הרבה יותר.

10 שאלות × 3 מנועים עם השהיות של 20-60 שניות = **בערך 40-50 דקות**. זו משימת רקע, לא משהו שמחכים מולו.

לריצה על מנוע אחד בלבד:

```bash
node src/cli.js run goldfish --engine=chatgpt
```

**Gemini ו-Google AI Overviews דורשים `--cdp`.** גוגל חוסמת דפדפן שנפתח על ידי אוטומציה: ב-Gemini היא מסרבת להתחבר, ובחיפוש היא מציגה "אני לא רובוט". שניהם עוברים דרך הדפדפן האמיתי שלך:

```bash
node src/cli.js browser
node src/cli.js run goldfish --engine=google_aio --cdp
```

אם גוגל חוסמת בכל זאת, המערכת **אומרת את זה מפורשות** ולא מתחזה ל"לא הוצג בלוק AI" — ואחרי שלוש חסימות ברצף היא עוצרת במקום לבזבז עוד עשר דקות. השאלות שלא נמדדו אינן נספרות בציון.

### 4. אימות ידני

בתוכנה, לשונית **2. הרצה** → כפתור **אימות** בשורת הבדיקה. הדף נפתח, מסמנים,
לוחצים **שמור אימות** — וזהו.

מהטרמינל, כשצריך:

```bash
node src/cli.js review 1
```

מייצר דף HTML שנפתח בדפדפן, ובו לכל תוצאה: **הטקסט המלא של התשובה** כשבתוכו שם העסק מסומן בירוק והמתחרים בכתום, צילום המסך, והסימון האוטומטי. מסמנים מה שלא נכון, והדף נותן שורת פקודה אחת:

```bash
node src/cli.js verify 1 --set=12:2,13:n
```

(הדף שהממשק מגיש הוא אותו דף בדיוק, אלא ששם השמירה נכנסת ישירות למסד ואין מה להעתיק.)

עסק שמופיע בתשובה ואינו צבוע הוא מתחרה שחסר בקובץ הלקוח — שווה להוסיף אותו ולהריץ `analyze` מחדש.

למי שמעדיף את הטרמינל, `node src/cli.js verify 1` עדיין עובר תוצאה-תוצאה: Enter משאיר, מספר 0-3 משנה.

**זה שלב חובה לפני שליחה ללקוח.** הזיהוי האוטומטי בעברית לא מושלם, במיוחד בזיהוי "המלצה מפורשת".

כשהמיקום נגזר ממתחרים מוכרים בלבד ולא ממבנה רשימה, מוצגת אזהרה בשורה. במקרה כזה בדוק בצילום המסך — ייתכן שהעסק מופיע נמוך יותר ממה שנרשם, כי עסקים שאינם ברשימת המתחרים אינם נספרים.

### 5. מיתוג הדוח (פעם אחת)

בתוכנה, לשונית **3. דוח** → **מיתוג הדוח** → שם המשרד, שורת תיאור, טלפון,
מייל, אתר, ובחירת קובץ לוגו → **שמור מיתוג**.
כל שדה אופציונלי; מה שריק לא יופיע. התג בכותרת התוכנה מראה אם המיתוג פעיל.

הלוגו נשמר ל-`config/logo.png` (או `.jpg`/`.webp`/`.svg` לפי הקובץ שבחרת), עד 2 מגה.

מהטרמינל, אם אתה מעדיף לערוך את הקובץ ישירות:

```bash
cp config/brand.example.json config/brand.json
```

הלוגו **מוטמע** בתוך ה-HTML וה-PDF ולא מקושר, כך שהקובץ נשאר עצמאי ואפשר לשלוח אותו כמו שהוא.

> `config/brand.json` והלוגו נמצאים ב-`.gitignore`, כי הריפו ציבורי ואין סיבה שהטלפון והמייל שלך ייסרקו משם. אם אתה מעדיף שהם יישמרו בגיט — הסר אותם מהקובץ. **שמור עותק** של השניים, אחרת שכפול נקי של הריפו יאבד אותם.

### 6. דוח

```bash
node src/cli.js report 1
```

יוצר HTML ו-PDF בתיקיית `reports/`.

**לדוח אחד שמאחד כמה ריצות** — למשל מנוע בכל ריצה — מפרידים במספרים בפסיק:

```bash
node src/cli.js report 1,5,7
```

**להשוואה למדידה קודמת** — זה מה שהופך בדיקה חד-פעמית למעקב:

```bash
node src/cli.js report 8,9,10 --vs=1,5,7
```

מוסיף סעיף מגמה: השינוי בציון, גרף שמשווה את שלושת המדדים בין המדידות, וטבלה של **אילו שאלות בדיוק זזו ולאן**. אם שום דבר לא זז, זה נאמר במפורש — יציבות היא ממצא, לא עמוד ריק.

הדוח יכלול עמודה לכל מנוע וטבלת **"לפי מנוע"** עם ציון נפרד לכל אחד, כי ציון אחד על שלושה מנועים מסתיר את הסיפור: אותו עסק יכול להיות ראשון בגוגל ונעדר ב-ChatGPT. אותה שאלה באותו מנוע שמופיעה בשתי ריצות נספרת פעם אחת, לפי המאוחרת.

### 7. ייצוא לכלי הידני

```bash
node src/cli.js export 1
```

מייצר JSON שנטען ישירות בשדה הייבוא של הכלי הידני (מצורף ב-`manual-tool/index.html` — פותחים בדפדפן, לשונית "הרצה" → "ייבוא").

תא שלא נמדד יוצא כ-`status: null` עם `measured: false` — לא כאפס. הפקודה מדפיסה כמה תאים כאלה יש. שאלות שלא התקבלה עליהן שום תוצאה נשארות בייצוא עם תאים ריקים, כדי שלא ייראה כאילו לא נשאלו.

## פקודות נוספות

```bash
npm run app                       פתיחת התוכנה (מה שהקיצור עושה)
node src/cli.js runs              רשימת כל הריצות
node src/cli.js analyze 1         ניתוח מחדש על הטקסט השמור, בלי לפנות שוב למנועים
```

**`analyze` הוא חשוב:** אם שיפרת את רשימת הווריאציות או את לוגיקת הזיהוי, אתה מריץ אותו והתוצאות מתעדכנות — **בלי לבזבז עוד ריצה מול המנועים.** זו הסיבה שהאיסוף והניתוח מופרדים.

## כשמשהו נשבר

זה יקרה. הממשקים של ChatGPT ו-Gemini משתנים כל כמה שבועות, וכל שינוי שובר את הסלקטורים.

**קודם כל — האם הקוד תקין או שהסלקטור התיישן?**

```bash
npm run smoke
```

מריץ את הדרייבר האמיתי מול שרת מקומי שמדמה את ה-DOM. דורש דפדפן, לא דורש רשת.
אם הבדיקה עוברת — הקוד תקין והבעיה היא בסלקטורים בלבד. אם היא נכשלת — נשבר משהו בקוד עצמו.

**כל הסלקטורים יושבים בקובץ אחד: `config/engines.json`.** אין צורך לגעת בקוד.

התסמין: הודעה מסוג "שדה הקלט לא נמצא".

התיקון:
1. פתח את האתר בדפדפן, לחץ ימני על שדה הקלט → Inspect
2. מצא מזהה יציב (`data-testid`, `aria-label`, `id`)
3. הוסף אותו **בתחילת** הרשימה המתאימה ב-`config/engines.json`

המערכת מנסה את הסלקטורים לפי הסדר ולוקחת את הראשון שנמצא, אז הישנים יכולים להישאר.

config/engines.json    ← הסלקטורים. השכבה השבירה, מבודדת לגמרי
clients/               ← קבצי לקוחות
src/
  normalize.js         ← נרמול עברי והתאמת שמות
  analyze.js           ← קביעת status וחישוב הציון
  exportJson.js        ← בניית ה-JSON לכלי הידני
  questions.js         ← הצעת עשר השאלות מהתחום והעיר
  review.js            ← דף האימות שנפתח בדפדפן
  app.js               ← השרת המקומי של התוכנה. 127.0.0.1 בלבד
  app.html             ← הממשק עצמו
  db.js                ← SQLite
  run.js               ← תזמור הריצה
  report.js            ← דוח HTML/PDF
  cli.js               ← שורת הפקודה
  engines/             ← דרייבר לכל מנוע
data/                  ← בסיס הנתונים, צילומי מסך, קבצי התחברות
reports/               ← הדוחות
manual-tool/index.html ← הכלי הידני. יעד הייצוא. עצמאי, פותחים בדפדפן
test/
