# מנוע בדיקת נראות במנועי AI

בודק אוטומטית האם עסק מופיע בתשובות של **ChatGPT**, **Gemini** ו**תשובות ה-AI של גוגל**, מצלם כל תשובה, ומייצר דוח בעברית.

עובד דרך **דפדפן אמיתי** ולא דרך API — כי ה-API מחזיר תשובות שונות ממה שהלקוח באמת רואה, ובלי דפדפן אין צילומי מסך.

---

## התקנה

צריך **Node.js גרסה 20 ומעלה**. לבדיקה: `node -v`

```bash
cd geo-engine
npm install
npx playwright install chromium
```

בדיקה שהכל תקין:

```bash
npm test
```

אמור להציג 44 בדיקות לוגיקה ועוד 15 בדיקות-חוזה שעברו. **הן רצות בלי אינטרנט ובלי דפדפן** — הן בודקות את לוגיקת הזיהוי והציון, ואת ההתאמה בין הייצוא לכלי הידני.

---

## הרצה ראשונה

### 1. הגדרת לקוח

ערוך את `clients/example.json` או צור קובץ חדש לפי אותו מבנה, ואז:

```bash
node src/cli.js client:add clients/example.json
```

**השדה הכי חשוב הוא `nameVariants`.** בעברית אותו עסק נכתב בכמה צורות — "גולד פיש", "גולדפיש", "גולד שיווק", "Gold Fish". בלי הרשימה הזאת המערכת תדווח "לא מופיע" גם כשהוא כן מופיע. אותו דבר לכל מתחרה.

### 2. התחברות ל-Gemini (פעם אחת)

```bash
node src/cli.js login gemini
```

ייפתח דפדפן. תתחבר ידנית, ואז תחזור לטרמינל ותלחץ Enter. ה-session יישמר.

> **חשוב: השתמש בחשבון גוגל ייעודי לבדיקות.** לא בחשבון האישי ולא בחשבון העסקי. אוטומציה של הממשקים האלה עלולה לנגוד את תנאי השימוש, והסיכון המעשי הוא חסימת החשבון.

ChatGPT וגוגל עובדים בלי התחברות.

### 3. ריצה

```bash
node src/cli.js run goldfish
```

הדפדפן ייפתח **גלוי** — זה מכוון, דפדפן מוסתר נחסם הרבה יותר.

10 שאלות × 3 מנועים עם השהיות של 20-60 שניות = **בערך 40-50 דקות**. זו משימת רקע, לא משהו שמחכים מולו.

לריצה על מנוע אחד בלבד:

```bash
node src/cli.js run goldfish --engine=chatgpt
```

### 4. אימות ידני

```bash
node src/cli.js verify 1
```

עובר תוצאה-תוצאה. Enter משאיר כמו שזה, מספר 0-3 משנה.

**זה שלב חובה לפני שליחה ללקוח.** הזיהוי האוטומטי בעברית לא מושלם, במיוחד בזיהוי "המלצה מפורשת".

כשהמיקום נגזר ממתחרים מוכרים בלבד ולא ממבנה רשימה, מוצגת אזהרה בשורה. במקרה כזה בדוק בצילום המסך — ייתכן שהעסק מופיע נמוך יותר ממה שנרשם, כי עסקים שאינם ברשימת המתחרים אינם נספרים.

### 5. דוח

```bash
node src/cli.js report 1
```

יוצר HTML ו-PDF בתיקיית `reports/`.

### 6. ייצוא לכלי הידני

```bash
node src/cli.js export 1
```

מייצר JSON שנטען ישירות בשדה הייבוא של הכלי הידני (מצורף ב-`manual-tool/index.html` — פותחים בדפדפן, לשונית "הרצה" → "ייבוא").

תא שלא נמדד יוצא כ-`status: null` עם `measured: false` — לא כאפס. הפקודה מדפיסה כמה תאים כאלה יש. שאלות שלא התקבלה עליהן שום תוצאה נשארות בייצוא עם תאים ריקים, כדי שלא ייראה כאילו לא נשאלו.

## פקודות נוספות

```bash
node src/cli.js runs              רשימת כל הריצות
node src/cli.js analyze 1         ניתוח מחדש על הטקסט השמור, בלי לפנות שוב למנועים
```

**`analyze` הוא חשוב:** אם שיפרת את רשימת הווריאציות או את לוגיקת הזיהוי, אתה מריץ אותו והתוצאות מתעדכנות — **בלי לבזבז עוד ריצה מול המנועים.** זו הסיבה שהאיסוף והניתוח מופרדים.

## כשמשהו נשבר

זה יקרה. הממשקים של ChatGPT ו-Gemini משתנים כל כמה שבועות, וכל שינוי שובר את הסלקטורים.

**קודם כל — האם הקוד תקין או שהסלקטור התיישן?**

```bash
npm run smoke
```

מריץ את הדרייבר האמיתי מול שרת מקומי שמדמה את ה-DOM. דורש דפדפן, לא דורש רשת.
אם הבדיקה עוברת — הקוד תקין והבעיה היא בסלקטורים בלבד. אם היא נכשלת — נשבר משהו בקוד עצמו.

**כל הסלקטורים יושבים בקובץ אחד: `config/engines.json`.** אין צורך לגעת בקוד.

התסמין: הודעה מסוג "שדה הקלט לא נמצא".

התיקון:
1. פתח את האתר בדפדפן, לחץ ימני על שדה הקלט → Inspect
2. מצא מזהה יציב (`data-testid`, `aria-label`, `id`)
3. הוסף אותו **בתחילת** הרשימה המתאימה ב-`config/engines.json`

המערכת מנסה את הסלקטורים לפי הסדר ולוקחת את הראשון שנמצא, אז הישנים יכולים להישאר.

## מבנה הפרויקט

```
config/engines.json    ← הסלקטורים. השכבה השבירה, מבודדת לגמרי
clients/               ← קבצי לקוחות
src/
  normalize.js         ← נרמול עברי והתאמת שמות
  analyze.js           ← קביעת status וחישוב הציון
  exportJson.js        ← בניית ה-JSON לכלי הידני
  db.js                ← SQLite
  run.js               ← תזמור הריצה
  report.js            ← דוח HTML/PDF
  cli.js               ← שורת הפקודה
  engines/             ← דרייבר לכל מנוע
data/                  ← בסיס הנתונים, צילומי מסך, קבצי התחברות
reports/               ← הדוחות
manual-tool/index.html ← הכלי הידני. יעד הייצוא. עצמאי, פותחים בדפדפן
test/
  logic.test.js        ← בדיקות לוגיקה, בלי דפדפן
  export-contract.test.js ← מריץ את calc של הכלי הידני על ייצוא אמיתי
```

## כללי עבודה שאסור לשבור

**"לא נמדד" הוא לא "לא מופיע".** כשגוגל לא מציגה בלוק AI לשאילתה, זה נרשם `null` ולא נספר בציון. אם תספור את זה כאפס — תמכור ללקוח ציון שקרי. זה נכון בכל מקום שבו התוצאה יוצאת החוצה: בציון, בדוח ובייצוא.

**אין ערכי ברירת מחדל.** שדה שלא נמדד נשאר ריק ומסומן ככזה בדוח.

**אל תוריד את ההשהיות.** 20-60 שניות בין שאלות. חסימה עולה יותר מהזמן שנחסך.

**אל תשלח דוח ללקוח בלי אימות ידני.**

**אל תבטיח מיקום.** הדוח מנוסח כך שאין בו הבטחת דירוג — אל תשנה את הניסוח הזה.
