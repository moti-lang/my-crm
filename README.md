# ניהול לקוחות — CRM

אפליקציית קובץ־יחיד (`crm (1).html`) המבוססת React + Supabase. פותחים אותה ישירות בדפדפן, אין צורך בשרת.

## תצוגת מפה

לצד תצוגת הרשימה קיימת תצוגת **מפה** המציגה את הלקוחות לפי כתובתם, כשצבע הסיכה מייצג את מצב העסקה.
המפה בנויה על Leaflet + אריחי CARTO, והמרת הכתובות לקואורדינטות נעשית מול Nominatim של OpenStreetMap.
כל השירותים הללו חינמיים ואינם דורשים מפתח API.

### הגדרה חד־פעמית ב‑Supabase

תצוגת המפה דורשת שלוש עמודות בטבלת `clients`. הריצו את ה‑SQL הבא ב‑Supabase, בתפריט **SQL Editor**:

```sql
alter table public.clients
  add column if not exists address text,
  add column if not exists lat double precision,
  add column if not exists lng double precision;
```

ודאו שמדיניות ה‑RLS על הטבלה מתירה `select` ו‑`update` גם לעמודות החדשות (מדיניות ברמת השורה חלה ממילא על כל העמודות; אם הגדרתם הרשאות ברמת העמודה — יש להוסיף אותן שם).

בלי ההרצה הזו הרשימה תמשיך לעבוד כרגיל, אך שמירת לקוח תיכשל עם הודעה שמפנה לקובץ הזה.

### שימוש

1. בעת הוספה או עריכה של לקוח, מלאו את שדה **כתובת** (למשל `הרצל 12, תל אביב`). הכתובת מומרת לקואורדינטות בעת השמירה ונשמרת בשדות `lat`/`lng`, כך שאין המרה חוזרת בכל טעינה.
2. עברו לתצוגת **🗺 מפה** בראש המסך. הסינון לפי מצב וחיפוש החופשי חלים גם על המפה.
3. ללקוחות שנוספו לפני ההגדרה — פתחו את תצוגת המפה ולחצו על **מפה אותם עכשיו**. הפעולה עוברת על כל הלקוחות שיש להם כתובת ללא קואורדינטות וממפה אותם, בקצב של פנייה אחת לשנייה בהתאם למגבלת השימוש של Nominatim.
4. לחיצה על סיכה פותחת חלונית עם שם, מצב, טלפון לחיץ, כתובת וכפתור עריכה.

### התאמות

- `GEOCODE_COUNTRY` בראש הסקריפט מטה את תוצאות החיפוש לישראל. השאירו מחרוזת ריקה לחיפוש עולמי.
- `ISRAEL_CENTER` קובע את מרכז המפה ההתחלתי כשאין עדיין לקוחות ממופים.

### מגבלות

- Nominatim הוא שירות ציבורי בהתנדבות ומוגבל לפנייה אחת לשנייה. הוא מתאים לנפח של מערכת קטנה; למאות כתובות בבת אחת מומלץ שירות ייעודי.
- כתובת שלא נמצאה נשמרת כטקסט בלבד, הלקוח מסומן ברשימה כ"לא אותרה על המפה" ואינו מוצג על המפה.
- הקובץ טוען את React, Leaflet ואת האריחים מהרשת, ולכן נדרש חיבור אינטרנט.
